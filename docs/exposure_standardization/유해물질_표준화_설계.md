# 측정값 유해물질(유해인자) 용어 표준화 — 설계

대상: `측정값_유해물질_목록.md` 의 **원본 393종** (소스 `CaseExposureExtracted.current_data['측정값'][].물질`).
목적: 원문 표기를 **표준 유해인자 명칭 + 국제 식별체계(anchor)** 로 정리하되, 원표기·판정 이력을 감사 가능하게 보존.

---

## 0. 현황 진단 — "393종"은 실제 인자 수가 아니다

먼저 반드시 인지할 것: **393은 서로 다른 인자 393개가 아니라, 측정 맥락이 물질명 필드에 섞여 부풀려진 수치**다.

| 사실 | 수치 |
|---|---|
| 원본 고유 물질명 | **393** |
| 표준 유해인자 사전(283종)과 **정확 일치** | **32** (나머지 361은 미매핑) |
| **괄호 포함** 값 | 153 (38%) |
| 검체·측정맥락 꼬리표(요중/혈중/체외피폭/누적노출/청력검사/평균·범위 등) | ≈66 |
| **괄호만 제거해도** 줄어드는 고유값 | 393 → **287** (−106) |

유형 분포(휴리스틱): 유기·화학물질 후보 217 · 물리적 84 · 금속 42 · 분진/총칭 34 · 혼합·직업특이 11 · 생물학적 5.

즉 오염 패턴이 4가지로 명확하다 — **이걸 먼저 걷어내야** 국제식별체계(CAS/IARC) anchor 를 붙일 대상이 정해진다.

1. **측정맥락 혼입**: `수은 (혈중)` `수은 (요중)` `납 (혈중)` `알루미늄 (요중)` → 인자는 하나, 검체가 다를 뿐.
   `전리방사선(체외 피폭)` `포름알데히드(평균)` `PAHs (드로잉유)` → 측정 조건이 물질명에 붙음.
2. **동의어**: `방사선` = `전리방사선` = `방사선(이온화방사선)`; `TCE` = `트리클로로에틸렌`; `DMF` = `디메틸포름아미드`; `MC` = `디클로로메탄`.
3. **혼합물 전개**: `혼합유기용제(아세톤, 크실렌, 메틸에틸케톤)` — 한 셀에 성분 나열.
4. **상위↔하위 혼재**: `석면`/`백석면`; `크롬`/`6가크롬(불용성)`/`크롬(3가)화합물`; `분진`/`총분진`/`호흡성 분진`.

> 결론: 사용자가 제시한 프레임(CAS·IARC·별표21/22·JEM)은 **anchor 단계**의 기준으로 정확하다. 다만 그 앞에
> **정규화(맥락 분리)·동의어 통일** 두 단계가 선행돼야 anchor 를 붙일 "깨끗한 인자 후보"가 나온다.

## 1. 목표 산출물 — 두 개의 표

### (A) 동의어 매핑표 `유해물질_동의어맵` — 원표기 1행 = 393행
감사(audit)의 핵심. 원표기를 절대 훼손하지 않고, 무엇을→무엇으로 왜 바꿨는지 남긴다.

| 컬럼 | 설명 |
|---|---|
| `원표기` | 원문 그대로(측정값.물질 값). 불변. |
| `정규화표기` | 괄호·꼬리표 제거한 핵심 인자어 |
| `표준코드` | 아래 (B) 표준레지스트리의 PK (인자 하나로 수렴) |
| `측정맥락` | 분리해 낸 검체/측정조건 (혈중·요중·체외피폭·평균·범위 …) → 원래는 여기가 아니라 별 필드로 갈 정보 |
| `매핑근거` | 어느 계층으로 확정했는지 (CAS직결 / 별표21 / IARC / KOSHA GUIDE / 별표22 카테고리 …) |
| `검토상태` | 제안(LLM) / 확정(전문가) |

### (B) 표준 유해인자 레지스트리 `유해인자_표준` — 인자 1행 (≈150~200행 예상)
매핑의 목적지. 국제식별체계 anchor 를 여기에 1회만 부여.

| 컬럼 | 계층 | 비고 |
|---|---|---|
| `표준코드` | — | 내부 PK |
| `표준_국문명` | 국문규범 | 노동부 고시·별표21/22·화학회 명명 순 채택 |
| `유형` | 별표22 | 화학물질/금속/물리적/생물학적/인간공학적/사회심리적/분진·혼합 |
| `CAS_RN` | 국제ID ★1차 anchor | 순수화학물질만. 혼합·물리·생물은 공란 |
| `EC_No` | 국제ID | EINECS/ELINCS |
| `IARC_표기`·`IARC_group` | 학술 | 혼합물·직업특이 인자의 사실상 표준명 (welding fumes, wood dust …) |
| `별표분류` | 국내법 | 화학=별표21 대응 / 물리·생물 등=별표22 분류코드 |
| `표준사전코드` | 국내 | 기존 `ExposureDictionary`(283종) 코드 — 있으면 연결 |
| `CANJEM_agent` / `KoConJEM_인자` | 판정계층 | 국제·국내 JEM 상호운용용 (선택) |
| `환경부표기` | 부처병기 | 노동부와 다르면 별도 보존 |
| `근거출처` | — | 채택 표기의 1차 근거 문서 |

## 2. 파이프라인 (사용자 프레임을 실행 단계로)

```
[원표기 393]
  └ 0. 정규화        괄호·검체·측정조건 분리 → 정규화표기 + 측정맥락
  └ 1. 동의어 통일    약어·이표기·상하위 판단 → 표준코드 후보로 수렴 (≈150~200)
  └ 2. Anchor 부여    순수화학=CAS→EC ; 혼합·직업=IARC+KOSHA GUIDE ; 물리·생물=별표22 카테고리
  └ 3. 국내·판정 매핑  ExposureDictionary(283) 연결 + (선택) CANJEM/KoConJEM 인자 매핑
  └ 4. 검수·확정      전문가 confirm, 근거출처 기록, 감사이력 보존
```

**2와 3에서 사용자가 정리한 6계층 기준이 그대로 우선순위 규칙이 된다:**

- 국문 표준표기 채택 우선순위: ① 노동부 고시 노출기준/별표21 → ② KOSHA MSDS → ③ 별표22 분류 → ④ 대한화학회 명명 → ⑤ 국립국어원 외래어표기법(음역 판정: 톨루엔 vs 톨류엔).
- 1차 anchor: **CAS RN** (있으면 primary key 확정) → EC → UN → IUPAC(최종 준거).
- CAS 미부여(혼합물·직업특이): **IARC Monographs 표기 + KOSHA GUIDE(W/H 시리즈) 병합**. 예 `용접흄`→"Welding fumes"(IARC Grp1)+KOSHA W-15.
- 물리·생물·인간공학·사회심리: **별표22 체계** 준거 + ISO/ILO 보조.
- 부처 표기 충돌: 노동부 우선 + `환경부표기` 병기.
- 판정계층 정합성: 본 자료가 업무관련성 판정 사례집(1,625건)이므로 **산재보험법 시행령 별표3(업무상질병 인정기준)** 명칭을 화학 별표21/22와 교차 참조, 그리고 **CANJEM(258)/KoConJEM(26)** 인자체계 매핑 필드를 미리 확보.

## 4. 자동화 vs 검수 (방어적 실행)

- **LLM 제안 → 전문가 확정** 2단계. 393행을 배치로 LLM 이 `정규화표기·표준후보·CAS·유형·근거` 제안, 표본 검수(각 유형 20건) 후 확정. `standardize_units`/`standardize_confined_space` 와 동일한 검증 문법.
- **운영 DB 직접 변경은 별도 승인.** 1차 산출은 temp 의 매핑표(xlsx/csv)로만. `측정값.물질` 원본은 그대로 두고, 표준화 결과는 **새 필드**(`물질_표준`, `물질_CAS`, `측정맥락`)로 부가하는 것을 권장 — 원문 파괴 없이 조인. (밀폐공간처럼 값을 덮어쓰지 않음)
- **감사이력**: 동의어맵이 곧 이력. `원표기→표준코드` 매핑은 재실행 멱등, 근거출처 필수.

## 5. 열린 결정사항 (이걸 정해야 착수)

1. **측정맥락(혈중/요중/체외피폭/평균 등)을 어떻게?** — ⓐ 물질명에서 떼어 새 필드로 이동(권장) / ⓑ 물질명에 유지.
2. **상위↔하위 정책** — `석면`을 `백석면`으로 승격? 아니면 `석면(총칭)` 유지? `크롬`→`6가/3가` 강제 구분?
   원문에 근거 없으면 총칭 유지가 안전(측정단위 표준화 때와 같은 보수 원칙).
3. **목적지 표준** — 기존 `ExposureDictionary`(283종)에 매핑만 할지, CAS 기반 **신규 표준 레지스트리**를 만들지.
   283종은 판정계층 사전이라 측정 물질과 입도가 다를 수 있음(확인 필요).
4. **CANJEM/KoConJEM 매핑 필드**를 이번에 넣을지(학술 상호운용) vs 후속 단계로 미룰지.
5. **산출물 형태** — temp 매핑표(xlsx)만 / DB 부가필드까지 / epiref·부록표까지 반영.
